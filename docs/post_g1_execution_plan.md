## 2. 已定位的后续工作

以下来自当前源码静态审查及保存记录，不是新运行结果。行号可能随实现变化，以函数/符号定位。

| 项目 | 当前证据 | 下一步 |
|---|---|---|
| 图像节拍 | backend._sensor_loop每次wait(0.2)后再渲染/编码/写盘；保存记录RGB-D约1.488Hz、最大间隔1.601s | G2A分段计时、按计划调度、可靠写盘与服务器GPU验证；不能只降低interval |
| 快流记录 | IMU/编码器/关节约9.56Hz来自每10个控制tick发布一次；不等于控制只跑10Hz | 明确采样/控制/发布/持久化频率，分别报告sim与wall时钟 |
| 控制阻塞 | backend._handle持共享锁做TCP求解/检查，物理线程也需要此锁 | G2A复制状态后离锁求解，返回时检查版本；保持唯一物理所有者 |
| 图像时间 | _capture_rgbd先复制物理状态，渲染后才记measurement/arrival | 保存capture sim time、control tick、capture monotonic、render complete和arrival |
| 外参标签 | _image_transforms的部分T_base_*直接使用world xpos，没有左乘inverse(T_world_base) | G2A在非零底盘位置/朝向验证并修正；相机仍挂link4 |
| 覆盖率 | validator按观测速率反推expected，coverage通常约1 | 改为相对冻结采样计划的生成/交付/可靠写入覆盖 |
| 数据资格 | D2=true只检查若干记录存在；wrist-only又按原始传感器是否含Depth等判断 | 新增按policy profile定义的频率/对齐/来源/可观测性与allowlist门 |
| 真值出口 | 常规feedback含world_sim位置，当前过滤主要看truth等字样 | UI调试状态保留来源标签；训练/估计输入改为明确字段白名单 |
| 导航输入 | 激光世界方向射线标成base_link，内外时间混域；IMU缺失补零；encoder含真值底盘速度 | G3先修导航观测合同和估计输入，再接SLAM/Nav2 |
| 导航控制 | 所有底盘请求会取消臂；只有单EventSink；场景/Oracle依赖target_cube | G3分清导航与人工接管、增加非阻塞观测分发及可选抓取评分 |

G1记录的实际频率不能推断服务器性能。服务器GPU是否真正被EGL/Chromium使用必须现场验证。约9.56Hz的快流记录也不代表已经满足EKF所需频率。

  ↓
G2A 服务器执行基线 + 时钟/坐标/采集/操作可靠性
  ├─ G2B离线导出器可提前基于只读样例开发
  └─ G3可提前做ROS接口和场景设计
  ↓ 公共观测与后端接口冻结
G2B 原生数据→D0/D2 LeRobot出口   ║   G3 估计定位/建图/到点导航
  ↓ 合格数据和加载验证                ↓ 导航与接管验收
G4 ACT/语言VLA分包实验             G5 Frontier/VLN与近场交接
                    ↓
               联合任务与后续实车

“并行开发”不等于“同时跑多个仿真”。G2B只读数据和独立依赖，与G3的ROS包可并行；G2A和G3均触及backend，必须由同一底座所有者集成，不能同时重写该文件。

G2A完成后交付并停止。其他Goal由用户分别启动，不自动串行执行整条路线。

## 4. 下一首选Goal：G2A

范围：在服务器建立可追溯执行环境，修正采样时间、base外参、共享锁慢任务，改善5Hz图像profile及浏览器操作，补真实质量/资格门。

不含正式LeRobot导出、训练、新导航算法、自动视觉抓取、多场景采集或实车。

| 角色 | 唯一职责 |
|---|---|
| 主负责人 | 公共合同/版本、app与CLI、远端部署/作业工具、依赖、总配置、验收与报告 |
| A | backend采样/时钟/变换/锁与异步规划、相关传感器元信息和后端测试 |
| B | Three.js性能、输入/心跳/失焦链、服务器Chromium验证、前端构建 |
| C | recorder/validator/资格profile、只读质量报告、数据/因果测试 |

所有逻辑源码保存在本地，agent测试命令统一通过服务器作业队列。共享合同改动由主负责人处理。前端构建产物在服务器生成；需要回存时取指定bundle。

### G2A里程碑

1. **S0远端基线**：解析remote.md，服务器资源/环境/目录复核，上传文件清单并核hash；锁定专用runtime；不恢复旧A1。
2. **S1协议与定向修复**：时间域、capture tick、变换方向、兼容旧记录；规划离锁并丢弃过期解。
3. **S2性能与实际界面**：分段计时和deadline调度，实际服务器EGL/Chromium，真实页面事件在渲染/预览负载下工作。
4. **S3质量与门控**：计划覆盖率、时效/对齐、观测allowlist、profile资格；旧记录只读分析。
5. **S4有限验收**：新短片段及故障反例，相关G1回归一次，报告和小证据回传。

### G2A默认验收profile

正式运行前固定分辨率/内参、传感器周期、渲染设备、场景和判据。先恢复原有5Hz诊断profile，不将它宣称为20Hz训练profile。

- 服务器realtime运行，报告物理步长/控制周期、RTF、sim与wall频率、p50/p95/p99/最大间隔和各阶段延迟。
- 静止、底盘/臂运动两个短片段：预定窗口内唯一RGB-D平均wall频率≥4.5Hz，p99相邻间隔≤0.4s；预先声明初始化/收尾窗口，不能事后删掉卡顿段。
- 保持原分辨率；必要降分辨率仅能作为另一个明确profile，不混入原profile通过结果。可额外做一次有界10Hz探针，非G2A必需条件。
- 控制/租约/停止沿G1阈值，停止、断连、TCP预览负载下不能靠放宽TTL来“通过”。
- 控制事件无静默丢失，媒体成对、完整尾部；覆盖率相对计划采样数，记录跳过/过载/丢弃原因。
- 实测capture→render→publish→persist时延；图像和变换绑定同一capture状态，不能以render完成时间冒充采样时间。
- 窗口内图像、关节/夹爪引用和时钟映射可追溯；没有依据的旧时刻不能补造。
- 包含非零底盘平移/偏航的几何用例，以及仅q5/开口变化的相机/TCP不变量。

若服务器实测不能达到冻结目标，交付瓶颈与未完成项，不把换服务器/有GPU当作自动性能证明，不回本地运行。

## 5. G2B：离线数据出口

G2B的格式开发可提前；正式“因果合格”的输出需要G2A修复后的新记录。历史G1可用于格式冒烟和兼容读取，缺采样时间的图像不能被追认为精确对齐。

默认仅两个action profile：

- D0：body系vx/vy/wz三维动作；输入字段与估计/真值来源明确。
- D2：五个用户关节绝对目标+夹爪开度六维动作；观测为相应proprioception和明确图像键。

每个输出行引用原始frame/sample/control tick、选择的动作层和因果对齐规则。拒绝/取消/恢复/低频/缺失段不得静默并入合格示范。数据源仍为agent_ui时保留，不改标human_teleop。

LeRobot在服务器独立环境锁定release/commit及dataset格式；G1 runtime不升级。官方main在本次读取中声明Python≥3.12，G1使用Python3.10，应分离环境与文件边界。[官方依赖](https://github.com/huggingface/lerobot/blob/main/pyproject.toml)

完成官方loader读取、shape/单位/时间/来源映射验证即可；不训练、不以加载成功宣称策略有效。D1标签不足、D3联合学习、语义泛化后置。

## 6. G3：估计导航

在G2A公共时间/坐标门通过后联调。复用当前唯一MuJoCo后端，不并入旧A1的第二个Simulation。

先做原始激光几何/回波状态、轮测量/IMU、无真值里程计/EKF和TF；再接服务器Humble、slam_toolbox与Nav2。不直接把world_sim状态重命名为odom/map。

同时解耦target_cube/抓取Oracle依赖，增加两个简单导航场景；提供地图/位姿图保存和重启定位、人工设点、取消、接管、失效停止。保留导航期间有限机械臂活动，导航速度不能每tick取消臂。

建议首轮单种子ideal小集：

- 两场景×臂保持/有限活动：4个到达案例；
- 每场景保存后重启加载定位：2个案例；
- 取消/人工接管和扫描失联：各1个案例；
- 障碍、未知、地图外、无路目标及本体遮挡作为独立子检查，单列分母。

暂定到达≤0.10m、≤10°，平移≤0.01m/s、yaw≤0.03rad/s并持续0.6s；正式前冻结。Nav2 Action结果和隔离物理评分分别报告。

本Goal不含Frontier、VLN/VLA、自动抓取、毫米级停车、全身策略、任意起点重定位和实车。

## 7. 运行和交付纪律

后续一切安装、构建、测试、仿真、浏览器和导出均服务器执行。本地仅源码/配置/锁/清单/小报告；大数据留服务器。具体按[规范](server_execution_policy.md)。

不设置未经用户请求的token预算，但控制范围：少量完整工作包、有限案例、定向复验、最后一次相关完整回归；没有新修改不反复全测。agent无有效交付时记录事实并调整/接管，不循环派发空任务。

每个Goal交付远端可复现命令、版本化源/环境/模型/配置、逐例结果、失败与修复、server_artifact_index和未验证项。本轮只落盘这些计划，不运行或改动G1代码。
