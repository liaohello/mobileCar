## 1. 本轮结论

当前页面同时存在真实交互缺陷、缺少解释的正常禁用，以及与用户新需求冲突的旧协议限制。不能以“所有按钮都解禁”处理。

目标：一个入口、第一与第三视角同屏、机械臂滑杆连续控制、明确的底盘键盘驾驶模式、可理解的权限与录制状态、可核查的人类输入—下发—反馈链。先完成软件交互候选与服务器 fixture 验收，真实人类试点由用户另行启动。

### 3.2 按钮解释合同

共同 readiness 输出：`enabled / reason_code / reason_zh / next_action / pending / owner_session`，由明确状态派生。后端仍作权威校验，前端解释不能绕过它。

必须区分：未连接、未看到新画面、后端观测过期、未确认本人、未获得控制、其他会话占用、底盘未停稳、停止锁存、非本 Episode、请求处理中、保存未确认。

重复点击启用/开始/结束不得创建重复 session/Episode 或重复 finalize。按钮变灰不能是唯一反馈；禁用原因对键盘/触屏用户同样可见，不只放 hover tooltip。不要把后端 HTML 错页整段塞进红框，保留简短错误、HTTP/业务码、可展开详情。

## 4. 连续滑杆与六维目标

“六维”是 `[q1,q2,q3,q4,q5,gripper_width]`，不是末端 XYZ＋RPY。协议维持五轴 rad＋夹爪 m；可提供 deg/mm 显示，转换只在明确边界发生一次。

建议默认：显式启用连续控制后，滑杆 input 更新完整 desired vector；按已批准的 5Hz 上限发送，不用每个 DOM 事件发 HTTP，不做“停拖才发送”的长 debounce。若未来提高频率，另以端到端延迟与服务端能力冻结，不在本次任意调高。

- 一次只允许一个在途动作和一个可覆盖的最新待发目标；新拖动覆盖未发送的旧目标，禁止无限排队或落后追赶。
- 连续编辑期间不被状态轮询覆盖；其他维度继承当前明确期望目标。新会话初始化到真实反馈，恢复控制不得自动重放旧页面目标。
- pointerup/change/键盘步进结束后确保最后目标明确确认，或显示未送达；同值可保留服务器要求的 keepalive，但不能伪造新人类编辑事件。
- pointercancel、失焦、隐藏、离线、权限过期、换 Episode/后端 generation、停止事件均使旧队列失效；恢复连接不自动恢复非零底盘或旧动作。
- 后端继续执行 TTL、顺序号、权限/epoch、关节速度/限位、碰撞与原有 guard。前端停 timer 不能替代服务器 watchdog。
- 分层记录：raw input → requested vector → approved/limited vector → dispatch/reference → actual feedback。限幅要可见且可追溯，不把限幅目标冒充原输入。
- UI“停止运动”必须走有效后端取消/保持与底盘零速路径；不能只清前端 timer，也不自动张爪。无法取得确认时显示未知/未确认。

## 5. WASD/QE 与双视角的边界

源码依据：`src/mobilecar/ui/web/main.js:495–651` 已有底盘键位、松键零速、失焦释放与独立 `set_base_twist`；`scene-view.js:70–86` 已有第三人称相机和 OrbitControls。优先复用，不重写整套底盘/播放器。

首版：

- **观察模式**：仅观察/转动镜头；不产生运动。
- **机械臂模式**：底盘停稳确认后启用臂，键盘驾驶禁用并说明原因。
- **底盘模式**：明确退出机械臂控制并确认取消后启用键盘驾驶，臂维持批准安全目标。近场旧 v1 Episode 不允许混入驾驶动作；必要时明确结束当前记录，不能悄悄拆分。
- 同屏观察不要求同时行驶和抓取。移动中操作臂、单 Episode 跨驾驶/抓取的联合任务均不默认开放。

WASD/QE 是底盘，不是相机自由飞行；相机用鼠标拖动/滚轮。键盘只在页面可见、驾驶模式启用且不编辑输入框/使用 IME 时生效；处理大小写、event.repeat、多键/反向键、松键、pointercancel。A/D 为横移的依据是当前底盘 API，仍需和 capabilities 核对。

按住控制键才运动，松开即零速；Esc 发软件停止运动，不用于硬件急停承诺。断网时由服务端 watchdog 停止；前端显示停止尚未确认。不得靠持续心跳自动延续已经取消的人类驾驶意图。

新增辅助视图 profile 要保存 `operator_view_sources` 与 `policy_input_sources`：前者包含实际显示的 link4 与仿真第三人称，后者保持原模型输入或明确新集合。记录双视图各自 sample/source 时间；未证明同步时显示时间差/UNKNOWN，不硬配同帧。对操作者看过第三人称而模型未见的部分可观测差异另行披露，不自动授予训练资格。

按 M0→M3推进，设计内选择自行完成，不逐按钮向用户请求确认。优先解决实际控制语义，再做视觉整理。允许软件范围内集中修复审核问题；只对变化及未解决风险补测，不无故反复全量回归。

连续控制首先保留当前批准的 5Hz 上限，采用有界 latest-wins，完整 q5＋jaw 目标与 lineage。不要把滑杆改成 Cartesian 六自由度。不要删除权限、TTL、碰撞或停车限制来让按钮变亮。停运动、关发送器、录制结束、保存成功必须分别有明确状态与后端动作。

双视角使用新版本辅助视图 profile；旧 restricted profile、历史 Episode 和资格结论只读保留。第三人称 Three.js 不冒充真实相机。统一入口内分别呈现观察、停车臂控、底盘驾驶；不默认允许行驶中操作臂，也不把底盘命令塞进六维动作。

来源 human 仅来自用户真实输入。所有自动验收只用 automation/dev。保持真实人类事件与派生周期帧的区别；模型可见字段和操作者可见字段分别标记。

### 分工与验证

按 §7 分配文件唯一所有者，最多两名活跃子 Agent。若无可用非作者审核渠道，保全候选与可复核审核包，不能自签独立 PASS。

执行 §6 矩阵的相关软件验证。每个关键按钮至少正例与拒绝例；连续输入、失焦/断线、旧响应/旧 seq、结束保存幂等、双视图来源、输入框键盘隔离和模式互锁均为必测。测试证据绑定同一候选源/构建/config hash。

启动开发前 Gate：输入与所有权清楚、协议差异明确、没有冲突写者、不会访问真实控制 backend。交付 Gate：非作者确认无剩余 P0/阻断问题；完整请求和状态证据成立；未执行能力诚实标 NOT_TESTED。

### 交付与停止

新建隔离的 run 目录，保存 PLAN、问题/修改映射、BUTTON_CONDITIONS、验证矩阵与结果、source/bundle manifest、非作者审核、操作手册、FINAL_REPORT 与 CURRENT_STATE。最终状态是软件候选，可为 PASS_WITH_LIMITATIONS，但不得把物理/真人/部署写成 PASS。

完成软件候选即停止，不自动部署、录制或执行任何真实动作。必需验证/独立审核缺失时如实交付缺口，不自签 complete；Goal 状态按真实平台规则处理。最终只需给出结果、候选位置、遗留问题与下一次用户试点入口。

## 9. 本轮之外的待批准设计

- 本方案将 WASD/QE 明确定义为控制底盘，观察镜头由鼠标控制。若用户希望键盘飞行相机，作为另一个显式模式，不能复用同一按键同时驱动机器人。
- 第一版统一入口保留“驾驶/停车臂控互斥”；单条 Episode 内连续驾驶再抓取需要另行冻结跨阶段数据合同，不在旧 v1 记录内偷偷启用。
- 真实相机任务可见性必须实测后处理；本方案不预先移动相机或自动改变机械臂姿态来取得好画面。
