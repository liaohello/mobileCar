# 服务器执行与本地源码管理规范 v1

日期：2026-10-17。状态：用户已确定的后续执行约束；本文件不是已部署或已测试的声明。

## 1. 本地与服务器的边界

| 位置 | 保存和执行 |
|---|---|
| 本地mobileCar | 源码、必要模型/场景资产、配置、依赖锁、来源/部署清单、使用说明、精简验收报告、少量预览或索引 |
| 服务器 | 环境与依赖、前端构建、所有软件测试、MuJoCo/渲染、自动Chromium、ROS2、指标重算、导出、训练，以及原始数据/日志/数据集/检查点 |

本地允许文件读取、编辑、哈希和源码同步。不在本地或本机WSL创建新的测试环境、运行pytest/npm/colcon/仿真/自动浏览器。用户自行查看页面不计作自动测试；默认使用服务器桌面/远程访问，浏览器自动验证仍在服务器。

服务器不可用时继续不依赖执行的代码/文档工作，报告具体缺失，不以本地测试替代。不得为了执行新规范清理或搬移G1已有本地资产。

## 2. 连接、目录与环境

连接元信息从本地未跟踪的remote.md读取。当前proj_path配置为 ~/Desktop/mobileCar；执行时在服务器解析为绝对路径并确认实际目标。使用既有SSH私钥和已配置主机信息，不输出凭据，不把remote.md、私钥或口令上传到release。

本轮规划没有连接服务器；远端OS、GPU、ROS和包版本必须由执行Goal重新核查。旧工程10月15日的Humble/Ubuntu记录仅供参考，不是当前环境证明。

建议服务器布局：

~~~text
<server_project_root>/
  releases/<snapshot_id>/       # 冻结的源码/资产/配置/测试
  envs/<environment_id>/        # 独立runtime/export/ROS环境
  var/runs/<run_id>/            # 原始Episode、媒体和Oracle
  var/datasets/<export_id>/     # 导出数据
  var/maps/<map_id>/            # 地图与位姿图
  var/reports/<job_id>/         # 指标、JUnit、截图、日志索引
  var/jobs/<job_id>/            # PID/进程组、资源、退出状态
~~~

已存在目录先盘点，不覆盖活跃工程或旧任务。新release使用唯一ID，不用会删除远端文件的整树镜像选项。

G1 runtime基线为Python3.10、MuJoCo3.1.6，锁文件在仓库。服务器先创建专用环境复现它；不直接复用旧Conda或全局MuJoCo，不全局升级/卸载其他任务依赖。LeRobot导出和ROS桥接使用独立环境，记录兼容性和进程边界。

必要依赖优先装入专用环境或独立容器。确需系统ROS包时先复核发行版和权限，只补本Goal需要的组件，不重装整套系统，不修改其他任务的环境启动文件。

## 3. 源码冻结与同步

本地是源码主副本。主负责人制作文件allowlist和SHA-256清单，包含当前选定的未提交/未跟踪实现；Git HEAD不是完整源码身份。

允许同步：src、必要assets、configs、tests、scripts、tools、provenance、项目元信息、Python/Node锁文件和当前文档。

默认排除：remote.md/remote_server.md、凭据、.git、.venv、node_modules、__pycache__、本地runs、历史大日志、整个旧mujoco_learning、数据集及检查点。

上传后逐文件核对hash，再在服务器构建和运行。Node生成的bundle及source map属于远端构建产物；需要回存仓库时仅取明确文件，并记录生成源码和锁文件身份。

默认不在服务器手改另一份逻辑源码；需要修复时回到本地源码、生成新snapshot再部署。紧急远端修补必须以补丁回传并核对父版本，禁止双向同步覆盖本地并行工作。

每次测试报告绑定snapshot_id、文件清单hash、配置/模型hash、环境锁和服务器身份。不能混用不同release结果拼成一次完整通过。

## 4. 资源与任务管理

- 初期全项目同时最多一个物理仿真实例、一个对应mj_step所有者；允许其只读渲染/规划和写盘线程。
- 纯离线代码检查、数据导出可并行，但限制CPU/内存并记录资源；不因看到多GPU就启动多场景或训练。
- 分配明确GPU/渲染设备并记录实际EGL/OpenGL renderer；nvidia-smi可见不能代替MuJoCo/Chromium实际使用GPU的证据。
- 端口、run/输出目录、ROS_DOMAIN_ID和进程组独立。端口被占时换本任务端口，不结束占用者。
- 保存本任务PID、进程组、启动环境、输出、心跳和退出状态。只回收本任务创建且身份吻合的进程，不按进程名批量kill。
- 每个测试/动作/Episode有超时和优雅关闭，超时保留最后状态、停车证据和退出原因。不要无限重试同源同配置同故障。
- 定向验证优先；改动稳定后做一次相关完整回归。没有新修改/失败/疑点，不重复同一完整矩阵。

多agent先分配公共文件所有权，共用一个远端运行队列。A负责后端时，不允许另一条导航/导出线同时修改相同backend。独立Goal并行前先固定互斥目录和共享版本。

## 5. 结果存放与回传

原始Episode、RGB/Depth/Mask、完整运行日志、地图大资产、导出数据集、模型权重和环境留在服务器。本地不作为大数据中转站。

本地默认只回传：

1. 验收摘要、逐例表、JUnit、质量/性能JSON；
2. 部署/模型/源文件hash和环境版本；
3. 少量缩略图、关键失败截面；
4. server_artifact_index.json，含远端相对路径、job/run/episode/export ID、hash、大小、结果及复算命令。

默认每Goal回传包上限20MB，超过时生成远端索引并说明，不自动拉取完整媒体。用户明确指定的相关大文件另按请求处理。

远端路径和结果索引不包含口令或私钥。本地摘要必须标明“已在服务器执行”或“待执行”，不可把规划或历史G1结果写成新的通过。
