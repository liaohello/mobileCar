## 2. 首个 Goal：G1

**交付单场景、自由底盘的遥操作与数据闭环：操作者经界面驾驶接近方块 → 停稳 → 关节/TCP 操作 → 闭爪 → 抬升保持 → 保存、校验和回看完整记录。**

G1 包含：

1. 独立 Python 工程、配置、资产、迁移来源清单和启动入口。
2. 统一后端、命令仲裁、安全出口、状态和传感器接口。
3. 浏览器三维整车视图、键盘驾驶、五关节与夹爪滑块、TCP 位置目标及拖动预览。
4. 目标→IK→路径检查→有限速度执行→实际反馈；随时取消、停止和接管。
5. RGB、米制深度、激光、IMU、编码器、关节反馈、命令事件及任务事件录制。
6. Episode 生命周期、原生记录校验、只读回放、人工标签与隔离物理评分。
7. 少量真实 MuJoCo 动作、浏览器交互和任务记录，形成新的验收证据。

G1 不要求新建 SLAM、ROS2 部署、自主导航、Frontier、自动视觉抓取、自动底盘协同、严格六维到位、Leader Arm、LeRobot 格式导出、模型训练或实车运动。已有定位/视觉输出可以通过适配器接入并标明来源，缺失时显式不可用。

允许操作者参考第三人称三维视图。记录其视图来源；这类演示不自动具备“仅腕部 RGB 即可部署”的 VLA 资格。开发 agent 经相同界面操作时，来源记为 agent_ui，不能标成 human_teleop。

## 5. 先冻结的技术决策

### 5.1 动作与控制

- 底盘 body 系 [vx, vy, wz]：前、左、逆时针为正；具体轮序由测试证明。
- 臂目标使用五个用户角，内部 rad；夹爪目标为米制开口。模型角是后端内部/诊断字段，不与用户角混用。
- 不含某通道表示不更新该通道；停止必须显式表达，不能把缺字段当作零。
- 同一会话可拥有底盘和臂两个通道；不同控制源对同一通道互斥。软件停止覆盖所有来源。
- TCP目标和关节目标是同一arm组的互斥控制入口；夹爪也归该组，不能被另一个来源独立覆盖。
- 拖动和滑块修改默认只更新目标与预览，点击执行才发运动请求。键盘驾驶使用按住刷新、松开停止。
- 所有执行路径经过后端的强制仲裁、有效限位、路径/状态检查和有限速度/力执行。
- 手动接管取消旧计划，不自动恢复；世界目标保留，重新求解后显式执行。手动驾驶时不默认自动补偿机械臂。
- 请求TTL限定首次下发窗口；持续运动另受所有权租约约束。长臂计划由会话心跳维持权限，不通过重复提交旧目标续命；失去权限取消剩余运动并保持。
- 现有DLS包含完整朝向代价，必须适配为先满足位置容差、再改善可放松姿态，不能原样改名为位置优先。未输入朝向时采用提交时实际姿态作为软偏好，不能默认单位旋转。
- 预检与执行使用同一条同步时间参数化轨迹；若复用逐轴斜坡，则检查其实际参考轨迹。不能检查直线插值却执行另一条路径；跟踪偏离越界时取消/保持。

接触规则由A在M0明确：轮地接触允许，选定目标与指腹在抓取阶段的预期接触允许；非预期自碰撞、车体/机械臂与台面/环境接触拒绝或终止。规则同时用于预检和运行监视，不能把抓取所需接触一律当碰撞，也不能全局关闭接触检查。持物抬升时检查携带物体的碰撞包络，不能因允许指腹接触而忽略物体与环境碰撞；真实持物仍由物理接触维持。

### 5.2 模型与相机

- 使用动态臂 + 自由底盘的有效模型，不能误用旧生成目录的固定臂驾驶档。
- 不改相机挂载拓扑、不固定底盘来使案例通过、不瞬移物体、不添加吸附抓取约束。
- TCP 固定于夹爪导杆结构；开合不改变 TCP。改变 q5 后，相机完整变换不变，TCP 朝向与相机→TCP 关系改变。
- 图像处理使用采样时刻关节反馈及标定 FK；不以“最新关节”代替图像时刻状态。
- 界面渲染模型与物理模型同源；原始 RGB 不含目标手柄、真值或诊断叠加。

### 5.3 时间、运行与记录

- 先复用物理步长 1 ms、控制周期 10 ms；它们不等于已证明墙钟实时。
- 每个运行实例一个物理所有者。允许无mj_step权限的独立渲染、IK/碰撞和落盘线程，使用快照/独立副本与有界队列；控制循环不等待慢任务，返回时重新校验身份并丢弃过期结果。
- 租约由接收端单调时钟管理。浏览器绝对时间不作为有效期权威。
- 正式录制模式必须可靠保存控制事件；落盘故障使 Episode 失效并触发受控停车。
- 原始数据不可被导出/清洗覆盖，真值评估与默认策略观测隔离。
- G1 可声明 GT_DEBUG 运行：仿真世界位姿只供明确标注的控制调试、界面或 Oracle。它不等于完成估计定位；默认训练出口不得混入这些字段。

### 7.1 合同、逻辑与几何

覆盖非法值/限位、重复/乱序/跨代命令、所有权争用、接管、TTL、断连、软件停止锁存、Reset、过期计划、停止后不自动恢复。

测试相机不依赖 q5/开合、TCP 不依赖开口、q5 改变 TCP 相对相机朝向、图像时刻反馈对齐、规划副本不修改运行状态。

### 7.2 实际动力学

- 底盘前后、左右、双向旋转、一个合成输入及释放停稳。
- 五关节小幅正负运动，夹爪开合；保留目标与测量差异。
- 至少三个非平凡安全 TCP 目标完成预览、路径检查、执行与实际误差记录。
- 覆盖超限/不可达拒绝、终点合法但路径碰撞、执行中取消与接管。
- 检查控制输出限制、自由底盘反作用、夹爪持物和重力影响。
- 记录接收到停止后的制动开始延迟与实测停稳时间；暂停不计作停稳。

### 7.3 界面与数据

实际浏览器完成视角旋转/缩放、目标拖动、数值输入、滑块、驾驶、失焦、停止、录制和回放。文本输入焦点不触发驾驶；计划预览和实际机器人明显区分。

记录至少一条操作者经遥操作界面完成移动抓取的 Episode，并保留一条失败/取消/中断记录。不能用自动 Pick test 代替遥操作动作。开发 agent 的界面操作标记为 agent_ui；人类复核/正式人类采集单列，不作为G1必须等待的前置条件。

成功由隔离 Oracle 检查动态方块、双侧有效接触、抬升和保持，不用 UI 标签代替；人工评价单独保存。接触/目标真值不进入默认策略输入。

检查多频流、唯一帧、深度单位和有效掩码、原始请求、执行关联、录制队列/错误、正常排空、缺资产和异常结束；覆盖开启确认→运动→关闭停车→排空→新片段重开的生命周期。输出实际采样率、时间偏差、积压/丢帧及覆盖，不能复制同一帧凑频率。

- 通过校验的完整 Episode、异常 Episode、原始资产、隔离评分和数据质量报告。
- 分层验收报告、实际命令与退出状态、失败与修复记录、典型界面证据和未覆盖范围。

文件已创建、mock 通过、旧工程报告或界面动画不能单独满足完成定义。关键物理任务、真实界面或记录关联缺失时，不得将整个 Goal 标为完成。

## 9. 后续 Goal 路线

| Goal | 主要交付 | 并行与前置依赖 |
|---|---|---|
| G2 数据出口 | 原生 Schema稳定、D0/D2 LeRobot导出、固定频率对齐与加载验证、采集吞吐 | 可与G3并行；依赖G1动作语义与原始记录 |
| G3 导航与交接 | 按需适配已新增A1代码，建图/保存/重启定位/到点/人工接管；再做近场新观察与可操作性交接 | UI基础稳定后，B可轮换导航；A保留底座，C继续数据 |
| G4 学习基线 | ACT先验证近场模仿学习链，再评估语言条件VLA；VLN先输出waypoint/区域 | 训练依赖合格数据；VLN在线依赖G3；ACT不能直接称作语言VLA |
| G5 联合策略与探索 | Frontier多站、语言任务、VLN/VLA切换、有界重定位及统一评估 | 分模块验收后集成，不把到达导航点等同可抓取 |
| G6 实车适配 | 驱动、反馈、标定、通信、硬件停止与低速验证 | 协议研究可提前；真实运动另定范围与验收，不能拿仿真参数替代 |

首个 Goal 完成后交付并停止，不自动启动后续 Goal。

## 10. 尚需实测、但不阻碍 G1 的项目

精确线束边界、实车电机/舵机零位和动力学、相机实物标定、真实通信与硬件停止，以及训练帧率和相应数据覆盖均未最终验证。

G1 使用可追溯仿真 profile；软件参数允许在开发期有据调整，正式用例冻结后按版本重验。相机拓扑已经确认，不再将“是否改挂 TCP”作为待决项。
